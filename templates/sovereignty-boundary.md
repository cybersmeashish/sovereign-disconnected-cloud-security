# Sovereignty boundary record

Use one record per business process and site. The examples are synthetic. Obtain the relevant accountable decisions before using this template for an actual environment.

| Field | Decision to record |
| --- | --- |
| Process and scope | Business process, site, tenant, data subjects and permitted actions |
| Accountable owners | Process, security, platform, identity, keys, disclosure and recovery |
| Jurisdiction | Authoritative requirement, applicable version, decision owner and unresolved applicability |
| Data | Classification, permitted uses, prohibited disclosures, minimization and retention |
| Placement | Primary, backup, evidence and recovery locations; actual verification method |
| Operators | Eligible administrator/support roles, location, delegation, privileged actions and emergency access |
| Keys | Workload, release verification, backup and recovery custody; separation and recovery responsibilities |
| Suppliers | Runtime, support, licensing, update, exit and recovery dependencies |
| Connectivity | Connected sovereign, intermittent, strict air-gap, or one-way export model |
| Flows | Registered source, destination, direction, transport, owner and conditions |
| Exceptions | Decision owner, reason, expiry, compensating control and review trigger |
| Evidence | Design assumptions, implemented mechanisms, observed results and remaining gaps |
| Acceptance | Who approved which decision, and on what evidence? |

Preserve the distinction between data placement, operator authority, key custody, legal applicability and an observed technical control.
